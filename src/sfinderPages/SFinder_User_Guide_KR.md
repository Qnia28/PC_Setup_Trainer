# SFinder 도구 사용자 가이드

이 가이드는 QniaPC의 **SFinder** 메뉴에서 제공하는 도구의 사용법을 설명합니다.
`PC Solver`는 **하나의 구체적인 큐**를 직접 풀며, 나머지 페이지에서는 SFinder 스타일의 분석 기능을 웹 인터페이스로 사용할 수 있습니다.

SFinder 분석 페이지는 2줄부터 6줄까지 지원합니다. 별도의 PC Solver는 현재 4L, 5L, 6L 모드를 제공합니다.

---

## 공통 입력

### 필드 / Fumen
필드를 직접 그리거나 Fumen 코드 또는 Fumen URL을 붙여 넣을 수 있습니다.
`Lines`는 PC를 완성하기 위해 채워야 하는 목표 높이입니다. SFinder 분석 페이지는 **2줄부터 6줄까지** 지원합니다.

- `2-4L Mode`: 2줄, 3줄 또는 4줄
- `5-6L Mode`: 5줄 또는 6줄
- 이 두 모드 그룹은 분석 페이지에서 사용합니다. PC Solver에는 별도의 4L, 5L, 6L 버튼이 있습니다.
- 선택한 목표 높이보다 위에 블록이 있으면 계산할 수 없습니다.
- Chance / Minimals / Per-save minimals는 일반적으로 첫 번째 Fumen 페이지를 분석합니다.

### Queue
SFinder 스타일의 큐 패턴을 사용할 수 있습니다.

```text
TOILJSZ        하나의 정확한 큐
*p7            7개 미노의 모든 순열
*!             *p7의 별칭; 7개 미노의 모든 순열
[TILJS]!       지정한 미노의 모든 순열
T,*p7          고정된 T 다음에 7개 미노의 bag
*!{O>T}        O가 T보다 먼저 나오는 순서로 제한한 7개 미노의 bag
I[JS]![TO]!,*p2
A;B            두 브랜치를 모두 분석
```

세미콜론(`;`)으로 구분한 브랜치는 서로 다른 분석 케이스로 유지됩니다.
bag 표현식 뒤에는 중괄호로 순서 조건을 붙일 수 있습니다. `*!{O>T}`에서는 왼쪽의 O가 오른쪽의 T보다 먼저 나와야 합니다. 조건이 여러 개라면 `*!{O>T,L>S}`처럼 쉼표 또는 `&`로 구분합니다.

### Hold
`Use hold`를 켜면 일반적인 Hold 사용을 포함하여 계산합니다.
의도적으로 Hold를 사용하지 않는 경우가 아니라면 켜 두는 것을 권장합니다.

### Advanced 옵션
Minimals와 Per-save minimals에는 다음 두 가지 추가 설정이 있습니다.
이 항목들은 고급 설정입니다. `Advanced`를 열면 HiGHS와 Quality 설정이 표시되며, 패널을 닫아도 아래에 설명한 기본값은 그대로 적용됩니다. 두 백엔드와 품질 모드의 차이를 자세히 모르는 경우에는 기본값을 변경하지 않는 것을 권장합니다.

- `HiGHS: Auto`는 축소된 행렬을 기준으로 exact-cardinality 백엔드를 자동 선택합니다. HiGHS가 유리한 어려운 행렬에서만 불러옵니다.
- `HiGHS: On`은 축소 후 외부 exact-cardinality 증명이 필요한 경우 HiGHS를 사용하도록 허용합니다.
- `HiGHS: Off`도 Release 2.6의 생산 알고리즘을 그대로 사용하며, 최소 개수는 Rust/WASM 백엔드로 정확히 증명합니다. 구형 legacy Minimals로 전환하는 옵션이 아닙니다.
- `Quality: Fast`도 최소 해법 개수는 항상 정확합니다. 다만 같은 최소 개수의 집합 중 하나를 고르는 2차 품질 최적화에서 결정적인 고속 fallback을 사용할 수 있습니다.
- `Quality: Exact`는 최소 해법 개수뿐 아니라 2차 human-quality 선택까지 정확히 계산합니다. 어려운 행렬에서는 시간이 훨씬 오래 걸릴 수 있습니다.

HiGHS는 실제로 필요한 계산에서만 지연 다운로드됩니다. HiGHS를 사용한 계산이 끝나면 QniaPC는 다음 요청 전에 해당 솔버 Worker를 해제합니다.

# PC Solver

> **현재 필드와 하나의 구체적인 큐에 대한 실제 PC 해법을 찾습니다.**
> SFinder 패턴 도구와 달리, Tetris PC 플레이 중 현재 보이는 특정 큐를 직접 풀기 위한 기능입니다.

### 입력
- 필드 또는 Fumen
- 현재 PC Solver UI에서 선택하는 목표 줄 수: 4, 5 또는 6
- `TILJOSZ`만으로 이루어진 **구체적인 큐**
- 표시 모드: `One` 또는 `All`

PC에 필요한 미노 수는 다음과 같습니다.

```text
필요 미노 수 = (목표 줄 수 × 10 - 채워진 칸 수) / 4
```

### One minimal
큐 길이가 필요한 미노 수와 정확히 같으면 `One minimal`은 **선호 해법 하나**를 반환합니다.

솔버는 실제로 배치할 수 있는 순서가 더 많은 해법을 우선합니다. 동률은 결정적인 기준으로 처리하므로 같은 입력에는 항상 같은 선호 해법이 선택됩니다.

UI의 이름과 달리 이 기능은 minimum-cover 계산이 아닙니다. 구체적인 큐에 대한 선호 해법 하나를 선택합니다.

### All
동일한 정확한 큐 조건에서 `All`은 **서로 다른 모든 PC 해법**을 반환합니다.

### Save 모드
큐에 필요한 미노 수보다 **한 개 이상 많은 미노**가 있으면, 솔버는 처음 `필요 미노 수 + 1`개를 Save 계산에 사용합니다.

- `One`: 저장 가능한 미노별로 선호 해법을 표시
- `All`: 모든 해법을 Save T / I / L / J / O / S / Z 그룹으로 표시
- 필요한 `P+1`개 뒤의 미노는 무시

PC Solver에서는 `*p7`, `[TILJS]!` 같은 SFinder 패턴 문법을 사용할 수 없습니다.

---

# Chance

> **큐 패턴 전체에서 필드를 Perfect Clear할 수 있는 비율을 계산합니다.**
> PC 성공률과 실패하는 정확한 큐를 확인할 때 사용합니다.

### 입력
- 필드 또는 Fumen
- Queue
- Lines
- Use hold

### 결과
- `Chance`: PC 성공률
- `Success`: 성공한 큐 수
- `Total`: 확장된 전체 큐 수
- `Failed`: 실패한 큐 수
- 실패 큐 목록

예를 들어 `*p7`은 7개 미노의 5040개 순열을 모두 검사합니다.

Chance는 **PC 가능 여부**만 필요할 때 가장 적합합니다. 대표 해법 Fumen도 필요하다면 Minimals를 사용하십시오.

---

# Minimals

> **큐 패턴을 커버하는 데 필요한 가장 작은 해법 집합을 찾습니다.**
> 모든 큐에 대한 해법을 하나씩 보는 대신, 소수의 대표 PC 해법을 원할 때 사용합니다.

### 입력
- 필드 또는 Fumen
- Queue
- Lines
- 선택 사항: `Saves`
- 선택 사항: Result title
- Use hold
- HiGHS: Auto / On / Off
- Quality: Fast / Exact

모든 PC 해법을 대상으로 Minimals를 찾으려면 `Saves`를 비워 두십시오.

> 현재 웹 UI에서는 모든 해법을 지정할 때 `all`을 입력하지 않고 **Saves 입력란을 비워 둡니다.**

특정 Save 조건으로 제한하려면 `Saves`에 다음 형식의 조건식을 입력합니다. 괄호는 `||`, `&&`, `!`와 조합할 수 있습니다.

```text
T
T || I
TI
!O
```

Save 조건을 사용하려면 마지막 bag의 미노를 식별할 수 있도록 `*p7`, `[....]!`, `...pN` 같은 bag 정보가 포함된 SFinder 패턴을 사용해야 합니다.

### 결과
- PC/Save 조건을 만족하는 큐 수
- Minimal 해법 수
- 선택된 각 해법의 커버 수
- 결과 Fumen

선택된 해법은 **커버 수가 높은 순서**로 표시됩니다. 여러 해법의 커버 수가 같으면 결정적인 solution key를 기준으로 순서를 정합니다.

예를 들어 선택된 세 해법이 각각 300개, 200개, 120개의 큐를 커버한다면 그 순서로 표시됩니다.

### 해석 방법
Minimals는 단순히 개별 커버 수가 가장 높은 해법을 고르는 기능이 아닙니다.
먼저 **성공한 모든 케이스를 커버하는 해법 집합의 크기를 전역적으로 최소화**한 뒤, 선택된 해법을 보기 쉽게 커버 수가 높은 순서로 정렬합니다.

두 Quality 모드 모두 선택되는 해법 개수는 정확합니다. `Fast`와 `Exact`의 차이는 같은 최소 개수의 집합 중 어느 것을 선택할지에 대한 2차 품질 최적화뿐입니다. Minimals의 기본값은 `Quality: Fast`입니다.

Saves와 마찬가지로 Save 조건을 적용할 때는 마지막 bag 정보를 제공하는 패턴을 사용하십시오.

# Per-save minimals

> **가능한 각 Save 미노별로 대표/minimal 해법을 따로 찾습니다.**
> Save T, Save I 등의 결과를 각각 구분해서 보고 싶을 때 사용합니다.

### 입력
- 필드 또는 Fumen
- `Queue`
- Lines
- 선택 사항: Result title
- Use hold
- HiGHS: Auto / On / Off
- Quality: Fast / Exact

현재 필드에서 PC에 `P`개의 미노가 필요하다면 모든 입력 큐는 정확히 **P+1개**여야 합니다.

```text
필요 미노 수 = (Lines × 10 - 채워진 칸 수) / 4
큐 길이 = 필요 미노 수 + 1
```

예를 들어 5줄 필드에 26칸이 채워져 있다면 다음과 같습니다.

```text
남은 칸 수 = 50 - 26 = 24
필요 미노 수 = 6
큐 길이 = 7
```

### 하나의 정확한 큐
하나의 구체적인 큐를 입력하면, 가능한 각 Save 미노에 대해 실제로 플레이하기 좋은 선호 해법을 빠르게 선택합니다.

### 패턴 입력
큐 패턴 행렬을 입력하면, 각 Save 미노별로 **정확한 minimal cover 집합**을 계산합니다.

Per-save minimals의 기본값은 `Quality: Exact`입니다. 작은 행렬에서는 생산 엔진 내부의 exact shortcut을 사용할 수 있으며, 이는 의도된 동작이고 공개 legacy Minimals 경로로 전환되는 것이 아닙니다.

### 결과
Save T / I / L / J / O / S / Z별로 다음 항목을 표시합니다.

- 해당 Save의 가능 여부와 성공률
- Minimal 해법 수
- 해법 Fumen

Save 그룹에 해법이 여러 개 있으면 커버 수가 높은 해법부터 표시합니다. 현재 UI에서는 각 해법의 개별 커버 수를 숫자로 표시하지 않습니다.
